## PROJECT OVERVIEW

LEXSHIELD is a web-based legal case management and security system designed to support the interaction between administrators, lawyers, and clients.

The system provides tools for lawyer and client management, legal case management, secure document storage, appointments, video consultations, messaging, payments, security monitoring, phishing detection, notifications, and audit logging.

LEXSHIELD is designed with security, privacy, document protection, and responsive usability in mind.

# STORAGE ARCHITECTURE

LEXSHIELD uses a dual-storage concept for protected case documents.

## PRIMARY STORAGE

InfinityFree/local server storage can be used as the primary document storage location.

Documents may include:

* Case documents
* Legal PDFs
* DOC/DOCX files
* Scanned documents
* Evidence
* Private case attachments

## SUPABASE BACKUP STORAGE

Supabase Storage can be used as a secondary or backup storage provider.

The intended architecture is:

```
                LEXSHIELD
                    |
                    v
          Primary File Storage
            InfinityFree
                    |
                    v
         Capacity / Availability
                 Check
               /       \
              /         \
         Available     Near Limit
            |              |
            v              v
         Primary        Supabase
         Storage         Backup
```

The storage system records the storage provider and storage path associated with protected documents.

Encrypted files may use an .enc extension.

The objective is to keep sensitive case documents protected while providing an additional storage option when the primary storage becomes unavailable or approaches its configured capacity.

## IMPORTANT SECURITY NOTE

Case documents contain potentially sensitive legal information.

Do not expose document storage paths publicly.

Do not manually change encrypted document files.

Do not bypass the application's authorization controls.

Do not share private storage credentials.

Do not place sensitive credentials such as database passwords, API keys, private keys, or secrets inside public GitHub files.

# SECURITY FEATURES

LEXSHIELD contains multiple security mechanisms designed to protect the platform.

Security controls include:

1. PASSWORD HASHING

Passwords are stored using secure password hashing rather than plain text.

2. PASSWORD VERIFICATION

Passwords are verified using secure password verification functions.

3. CSRF PROTECTION

Forms and sensitive requests use CSRF protection.

4. SESSION SECURITY

User sessions are protected and controlled according to the user's role.

5. RATE LIMITING

Rate limiting helps reduce automated abuse and repeated authentication attempts.

6. OTP SECURITY

OTP verification can use expiration, attempt limitations, and secure storage.

7. PASSWORD RESET SECURITY

Password reset tokens are protected and designed for limited/single use.

8. ROLE-BASED ACCESS CONTROL

Administrator, Lawyer, and Client users have different permissions.

9. SQL INJECTION PROTECTION

Database operations use PDO prepared statements and parameterized queries in the application's database operations.

10. XSS PROTECTION

User-controlled output is escaped before being displayed where appropriate.

11. FILE VALIDATION

Uploaded files are validated before being accepted.

12. MALWARE SCANNING

ClamAV integration can be used to scan uploaded files for malware.

13. DOCUMENT ENCRYPTION

Protected case documents can be encrypted before storage.

14. PHISHING DETECTION

URLs and domains can be analyzed for phishing indicators.

15. AUDIT LOGGING

Important system and security activities can be recorded.

16. AUTHORIZATION CHECKS

Users are required to have permission to access protected records.

17. VIDEO JWT SECURITY

Video consultation access can use JWT-based authentication when the JaaS video provider is configured.

# TROUBLESHOOTING

## LOGIN DOES NOT WORK

Check:

* Username/email
* Password
* Account status
* OTP/verification requirements
* Internet connection

If the problem continues, contact the administrator.

## APPOINTMENT TIME IS NOT AVAILABLE

Possible reasons:

* Lawyer is unavailable.
* The date is blocked.
* The selected session reached capacity.
* Another appointment occupies the selected slot.
* The lawyer has not configured availability.

## DOCUMENT CANNOT BE UPLOADED

Check:

* File type
* File size
* Internet connection
* Storage availability
* File security scan result
* User permissions

If the file is rejected by malware scanning, do not attempt to bypass the security check.

## DOCUMENT CANNOT BE OPENED

Check:

* User authorization
* Case assignment
* Document status
* Storage provider status
* Storage configuration

Contact the administrator if the issue continues.

## VIDEO CALL IS NOT AVAILABLE

Check:

* Appointment status
* Meeting availability
* Video provider configuration
* JaaS configuration
* Internet connection
* Browser permissions

The video consultation service must be correctly configured on the server before secure video meetings can operate.

## PAYMENT STATUS HAS NOT CHANGED

Payments may require administrator review.

Check:

* Payment submission status
* Uploaded proof
* Review status
* Administrator processing
